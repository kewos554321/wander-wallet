# Remove the v1 interface — implementation record

> **For agentic workers:** This plan has already been executed. It is kept as a record of the decisions and verification steps.

**Goal:** Remove v1, the UI-version switch, and v1-only code, after porting the onboarding tour to v2.

**Architecture:** Routes render their v2 page directly. The tour mounts on the v2 overview when onboarding is incomplete. Version plumbing and v1-only modules are deleted; shared API, Prisma, hooks, and UI primitives stay.

**Tech Stack:** Next.js App Router, React, TypeScript, driver.js, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-04-remove-ui-v1-design.md`

## Global Constraints

- No Prisma migration and no destructive data change.
- Old `?ui=v1` links must still render v2.
- Keep `components/ui/*` that admin/demo still use.
- `npm run lint` must not add errors; `npm run build` must pass.

## Review Focus

- A user with `onboardingCompleted=false` sees the tour only after the overview data renders.
- The tour does not restart when its callbacks change.
- An old `?ui=v1` bookmark renders the v2 page instead of a 404.
- Deleting v1 does not remove shared hooks/APIs used by v2.
- Settings no longer exposes a way back to v1.
